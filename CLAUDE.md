# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Live Docs (Context7)

Before writing any code that uses a library, framework, SDK, or platform API — including Next.js, Mongoose, NextAuth, and Zod — pull the current docs through Context7 first. Do **not** rely on training data for API signatures, configuration, or version-specific behavior; verify them against the fetched docs. If Context7 has no entry for a library, say so explicitly before proceeding.

## Next.js 16 — read the docs first

This repo runs **Next.js 16.4.3**, which has breaking API, convention, and file-structure changes from older versions. Before writing any Next.js code, read the relevant guide in `node_modules/next/dist/docs/` (resolved from the repo root) and heed deprecation notices. See `AGENTS.md` — that block is auto-regenerated by `next dev`, so commit it with your work rather than deleting it.

## React/Next.js performance — use the skill

This repo has the **`vercel-react-best-practices`** skill installed (Vercel Engineering's React/Next.js performance guidelines). Invoke it via the Skill tool **before writing, reviewing, or refactoring any React component, Next.js page/layout, data-fetching code, or Server/Client Component boundary**, and whenever a task touches bundle size or render performance. Follow its guidance alongside the Context7 live docs and the Next.js 16 guides above.

## Stack & structure

- TypeScript (strict), React 19, Tailwind CSS v4, npm (`package-lock.json`).
- App Router lives at the repo root in `app/` — there is **no `src/` directory**.
- Import alias: `@/*` → `./*` (root-relative).

## Commands

- `npm run dev` — dev server (Turbopack)
- `npm run build` / `npm run start` — production build / serve
- `npm run lint` — ESLint (`eslint-config-next`, core-web-vitals + typescript)
- No test framework is configured yet.

## Gotchas

- `next.config.ts` enables non-default flags: `cacheComponents`, `partialPrefetching`, and a Turbopack rule routing `*.css` through `@tailwindcss/turbopack`. Keep these in mind when debugging caching, prefetch, or CSS behavior.

## Doc Convention

Whenever a new file is created in `/docs`, add it to the **Project Docs** section below with one line on what it covers and when to read it.

### Project Docs

- [`docs/architecture.md`](docs/architecture.md) — Rendering model (Server/Client Components), directory layout (`app/`, `lib/`, `components/`), and naming conventions. Read before adding a new file, folder, or Server Action.
- [`docs/database.md`](docs/database.md) — MongoDB + Mongoose: single cached connection, models in `lib/db/models`, schema conventions (strict, timestamps, indexes), and the user-scoped query rule. Read before writing a model or any query.
- [`docs/auth.md`](docs/auth.md) — NextAuth sign-in/sessions, middleware-protected `app/(dashboard)/*` routes, the public `/user/[handle]` profile, and server-side identity enforcement (session-derived `userId`, ownership checks). Read before adding a route, Server Action, or anything that reads the signed-in user.
- [`docs/coding-standards.md`](docs/coding-standards.md) — TypeScript strict-mode rules, Prettier/ESLint, import ordering, component conventions (function declarations, typed props, no default exports outside route files), and async/error style. Read before writing any code.
- [`docs/routing.md`](docs/routing.md) — Public routes, the `(dashboard)` and `(auth)` route groups, middleware protection, per-route `layout`/`loading`/`error` files, and the Route Handlers (webhooks/callbacks only) vs. Server Actions rule. Read before adding a route, route group, or API handler.
- [`docs/errors-and-validation.md`](docs/errors-and-validation.md) — Zod validation at the Server Action boundary (shared schemas in `lib/validation`), returned typed validation errors vs. thrown unexpected errors caught by `error.tsx`, logging, and never leaking internals to the client. Read before writing a Server Action or error boundary.
- [`docs/data-fetching.md`](docs/data-fetching.md) — Reads run in Server Components (direct DB, no internal fetch), query scoping by `userId`/`handle`, caching with fetch cache / `unstable_cache` and tag-based `revalidateTag`, and Client Components receiving data as props. Read before adding a query or data-loading component.
- [`docs/data-mutations.md`](docs/data-mutations.md) — Writes are Server Actions (never API routes) following a fixed order: check session, validate with Zod, scope to `userId`, write, then `revalidatePath`/`revalidateTag`; actions return a typed result and don't throw for expected failures. Read before writing a create/update/delete action.
- [`docs/design-system.md`](docs/design-system.md) — Design foundations (color, type, spacing, tokens) pulled from the design-system source. Read before styling anything or choosing tokens/Tailwind utilities.
- [`docs/ui.md`](docs/ui.md) — UI component contracts (props, variants, states) for the React primitives. Read before building or using a shared component.
- [`docs/testing.md`](docs/testing.md) — Unit tests with Vitest (pure functions and Zod schemas, as `*.test.ts` beside the file), Playwright MCP end-to-end QA via the `run-qa-suite` skill (no `/e2e`, config, or committed `.spec.ts`), Server Actions tested through QA rather than mocked, a separate `MONGODB_URI_TEST` database in `.env.test`, and fully independent tests. Read before writing a test or running QA.
- [`docs/security.md`](docs/security.md) — Secrets in environment variables (`.env.local` gitignored, `.env.example` as template), security headers in `next.config.ts` (CSP, X-Frame-Options, Referrer-Policy), rate limiting on sign-in and link creation, and user-generated-content handling (escaping, `rel="noopener noreferrer"`). Read before adding a secret, touching headers, exposing an endpoint, or rendering user content.
- [`docs/git-conventions.md`](docs/git-conventions.md) — Conventional Commits (feat/fix/docs/refactor/test/chore) with imperative subjects, `<type>/<feature>` branch naming, one-feature-per-branch merged via pull request (never straight to `main`), and the required human review step. Read before committing, naming a branch, or opening a PR.
